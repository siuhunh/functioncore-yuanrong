# runtime异常后处理


## runtime异常后处理 Story 整体设计

### 功能描述
- runtime 异常后，重启进程，POD不退出，仍然可用
- runtime 异常后，异常信息正常准确反馈
- runtime 异常重启阶段，worker仍然能接受请求



### 场景分析

runtime在执行用户函数时，可能会触发我们的保护限制，例如内存溢出，文件夹占用过大，当前的处理方式是返回错误后，退出当前pod,这种处理方式，容易造成资源浪费，且重新特化pod会增加耗时


### 方案详细设计

#### 现状分析

当前FunctionGraph采用的方式是，runtime有异常的时候，反馈出异常后，重启runtime，复用此POD，发给worker的消息，先缓存起来，待到runtime重启成功后，再发给runtime处理

2.worker增加消息缓存队列，在收到请求后，放入消息队列中，在runtime正常后开始处理

## 可信软件
