# 【runtime】Go函数（Go 1.x）新增


## 1. Story整体设计
### 1. 功能描述
1）worker 适配V1版本的go runtime，支持go 语言函数运行，支持init接口，支持invoke 调用，支持日志获取，支持计费。
2）runtime-manager 支持go runtime的启动，支持setgid，setuid，挂载磁盘，OOM。
3）支持环境变量，委托信息的传递。
4）支持统一镜像打包

### 3. 方案详细设计
#### 3.1 worker适配V1版本的go runtime（1.x）
worker适配V1版本的go runtime（Go1.x），支持go 语言函数运行，支持init接口，支持invoke 调用，支持日志获取，支持计费。 
（1）worker适配V1版本的go runtime：在worker的runtime包下新增go1x包，并实现runtime接口；runtime client与server通讯方式为http+rpc(与V1版本一致)。
（2）支持go语言函数运行：特化函数实例时启动用户上传代码包的二进制文件，然后worker发送invoke调用到该进程; 
    生成go1.x函数二进制文件操作如下：
    1.用户下载FunctionGraph的Go RUNTIME SDK，解压到/home/fssgo目录，然后创建函数文件，并实现如下接口：
    func Handler(payload []byte, ctx context.RuntimeContext) (interface{}, error)
    2. 然后进行编译
    $ cd /home/fssgo
    $ go build -o handler test.go
    handler是函数入口，可以自定义
    3. 打包
    $ zip fss_examples_go1.x.zip handler
    [引用](https://support.huaweicloud.com/devg-functiongraph/functiongraph_02_0441.html )
（3）支持init接口：1.x不支持init接口（1.8支持）
（4）支持invoke接口：Function.Invoke（未实现）
（5）支持healthCheck接口：Function.HealthCheck（未实现），用于HotLoad检查runtime是否ready
（6）支持日志获取（获取标准输出，可参照custom和http runtime，未实现）
（7）支持计费（已有）; 启动二进制文件也需计费；首次实际调用超时时间 = 配置调用超时时间 - 启动二进制文件耗时


#### 3.2 runtime-manager支持go runtime的启动
runtime-manager支持go runtime的启动，支持setgid，setuid，挂载磁盘，OOM。 
(1) runtime-manager支持go runtime的启动：新增runtime（go1.x）；构造exec.Command，exePath为'/opt/function/code/${函数执行入口}'，
    函数执行入口与用户上传的代码包中的可执行文件名保持一致。例如：用户编译的可执行文件名为handler，则填handler。
    启动go runtime需传递环境变量RUNTIME_API_ADDR，V1为127.0.0.1:28923，在V2使用127.0.0.1:31539
(2) 支持setgid，setuid，挂载磁盘，OOM （功能已实现）

#### 3.3 支持环境变量，委托信息的传递。 
V1 go1.x runtime sdk支持的环境变量如下：
RUNTIME_API_ADDR：127.0.0.1:28923 需补充（V2使用127.0.0.1:31539）
RUNTIME_TIMEOUT（已有）
RUNTIME_PROJECT_ID（已有）
RUNTIME_PACKAGE（已有）
RUNTIME_FUNC_NAME（已有）
RUNTIME_FUNC_VERSION（已有）
RUNTIME_MEMORY（已有）
RUNTIME_CPU（已有）
RUNTIME_USERDATA（已有）
RUNTIME_HANDLER（已有）
RUNTIME_INITIALIZER_HANDLER（已有）
RUNTIME_INITIALIZER_TIMEOUT（已有）
RUNTIME_ROOT（已有）
RUNTIME_CODE_ROOT（已有）

委托信息：
worker发送Function.Invoke请求需带上如下请求头:
X-CFF-Request-Id
X-CFF-Access-Key
X-CFF-Secret-Key
X-CFF-Auth-Token
X-CFF-Security-Token

#### 3.4 支持统一镜像打包
基础镜像不用安装go, fusion镜像不用添加go runtime代码，因为go 1.x函数执行方式为启动用户上传代码包中的二进制文件然后发送invoke请求。

#### 3。5 其他
适配functionGraph错误响应，functionGraph错误码转换为元戎错误码，错误消息直接使用functionGraph原来的错误消息。
| **序号**  | **场景**                                                  | **错误码** | **错误消息**                             | **对应元戎错误码**                             |
| -------- | --------------------------------------------------------- | --------- | -------------------------------------- | ------------------------------------------- |
| 1        | invoke请求Payload为nil                                     | 400       | bad request parameters                 |  暂无                                        |
| 2        | 执行Handle接口用户函数实现，返回err不为空                       | 500       | 构造errormessage, 其中errorType为 FunctionReturnError | 4002（用户函数中未捕获的异常）      |
| 3        | 响应消息体太大                                              | 507        | 构造errormessage, 其中errorType为 FunctionResponseTooLarge  | 4004 （函数返回值内容超平台限制）|
| 4        | 处理invoke请求panic                                        | 555        | panic信息                               |  4002 （用户函数中未捕获的异常）                  |
| 5        | NewHandler，handlerFunc为nil                              | 400        | handler is nil                          |  4001（找不到函数入口）                         |
| 6        | handlerFunc类型不是Func                                    | 400        | handler kind %s is not Func            | 4001（找不到函数入口）                           |


go1.x runtime和其他runtime不同点，例如nodejs
| **序号**  | **功能**                                                   | **go 1.x**                         | **nodejs**                             |
| -------- | ----------------------------------------------------------- | ------------------------------| ---------------------------------------- |
| 1        | 初始化入口                                                    | 无                            | 有 |
| 2        | 依赖包功能                                                    | 无                            | 有 |
| 3        | return返回参数个数                                            | 函数结果和err                   | 函数结果                                 |
| 4        | 执行函数方式                                                  | 执行用户上传二进制               | 动态加载用户函数文件并执行 |
| 5        | 启动runtime是否计费                                           | 计费                           | 不计费 |
| 6        | 函数执行入口                                                  | 与用户上传的代码包中的可执行文件名一致 | 文件名.可执行函数名 |
