# 自定义运行时兼容FunctionGraph已有自定义运行时

关联AR： AR-20210630-001-008：自定义运行时； 兼容FunctionGraph已有自定义运行时

## 1. Story 整体设计
### 1.1 功能描述
元戎自定义运行时兼容 FunctionGraph 已有自定义运行时兼容，使 FunctionGraph 融合用户无感知，无需修改用户代码  
### 1.2 场景分析
#### 部署文件说明
- **bootstrap（必须）**  
Custom Runtime 固定的可执行引导程序文件，由开发者创建同名可执行程序文件，通过自定义语言及版本实现，直接处理或者通过启动其他可执行文件来处理，完成函数运行时的初始化和调用。 
- **函数文件（必须）**  
开发者通过自定义语言及版本开发实现的函数程序文件。
- **运行时依赖的库文件或可执行文件（可选）**  
根据自定义语言及版本运行时需要，添加相关依赖的库文件或可执行文件。

#### 运行流程
```flow
st=>start: 开始框
opA=>operation: 检索可执行引导文件 boostrap
cond=>condition: 检索到且可执行
opB=>operation: 函数初始化
opC=>operation: 执行函数调用操作
e=>end: 结束框
st(right)->opA(right)->cond
cond(yes)->opB(right)->opC(right)->e
cond(no)->e
```

#### API 接口对比
##### FunctionGraph Runtime

| 接口URL  | 接口类型  |   说明  |
| ------------ | ------------ | ------------ |
|  http://$RUNTIME_API_ADDR/v1/runtime/invocation/request | POST | 用来获取下一个事件，响应正文包含事件数据 | 
|  http://$RUNTIME_API_ADDR/v1/runtime/invocation/response/$REQUEST_ID |  POST |  该接口将调用响应发送到FunctionGraph。在运行时调用函数处理程序后，将来自函数的响应发布到调用响应路径。 |
|  http://$RUNTIME_API_ADDR/v1/runtime/invocation/error/$REQUEST_ID | POST  |  将调用响应发送到FunctionGraph。在运行时调用函数处理程序后，将来自函数的响应发布到调用响应路径 |

> $REQUEST_ID 为获取事件的响应 header 中 X-Cff-Request-Id 变量值  
$RUNTIME_API_ADDR 为系统环境变量

响应标头信息说明

|  参数 | 说明  |
| ------------ | ------------ |
| X-Cff-Request-Id |  请求ID |
| X-CFF-Access-Key  | 租户AccessKey，使用该特殊变量需要给函数配置委托  |
| X-CFF-Auth-Token | 使用该特殊变量需要给函数配置委托  |
| X-CFF-Invoke-Type | 函数执行类型  |
| X-CFF-Secret-Key | 租户SecretKey，使用该特殊变量需要给函数配置委托  |
| X-CFF-Security-Token  |  Security token，使用该特殊变量需要给函数配置委托 |

##### 元戎 Runtime

| 接口URL  | 接口类型  |   说明  |
| ------------ | ------------ | ------------ |
|  http://$RUNTIME_API_ADDR/runtime/init/ready | POST | 函数初始化完成阶段，调用该接口，表示自定义函数进入ready阶段 | 
|  http://$RUNTIME_API_ADDR/runtime/invocation/next | POST | 函数获取调用事件 | 
|  http://$RUNTIME_API_ADDR/runtime/invocation/response |  POST |  函数正常处理完请求，将结果返回 |
|  http://$RUNTIME_API_ADDR/runtime/invocation/error | POST  |  函数处理请求时出错，将错误信息返回 |
> $REQUEST_ID 为获取事件的响应 header 中 X-Request-Id 变量值  
$RUNTIME_API_ADDR 为配置文件配置

#### 环境变量
环境变量说明

|  键 |  值说明 |
| ------------ | ------------ |
| RUNTIME_PROJECT_ID | projectID |
| RUNTIME_FUNC_NAME | 函数名称 |
| RUNTIME_FUNC_VERSION | 函数的版本 |
| RUNTIME_PACKAGE | 函数组  |
| RUNTIME_HANDLER | 函数执行入口 |
| RUNTIME_TIMEOUT | 函数超时时间 |
| RUNTIME_USERDATA  | 用户通过环境变量传入的值 |
| RUNTIME_CPU  | 分配的CPU数 |
| RUNTIME_MEMORY  | 分配的内存 |
| RUNTIME_CODE_ROOT  | 包含函数代码的目录 |
| RUNTIME_API_ADDR  | 自定义运行时API的主机和端口 |

用户定义的环境变量也同 FunctionGraph 环境变量一样，可通过环境变量获取方式直接获取用户定义环境变量

### 1.3 方案详细设计
1. 适配 FunctionGraph Runtime 对外接口  

新增 Custom Runtime 内置配置文件 custom-runtime-config.yaml，用于定义元戎和 FunctionGraph 的一些接口 URL，响应标头，环境变量 key 信息  
两个内置配置文件分别放置在 build/runtimemanager/config 和 build/worker/config 目录下，定义完成后一般不做修改。通过构建脚本自动选择一份配置文件,生成 FunctionGraph custom Runtime 或者元戎 custom Runtime

    {
      "serverUrl": {
        "nextPath": "/v1/runtime/invocation/request",
        "responsePath": "/v1/runtime/invocation/response/{request_id}",
        "errorPath": "/v1/runtime/invocation/error/{request_id}"
      },
      "serverHeaders": {
        "headerInvokeIDKey": "X-Cff-Request-Id",
        "headerAccessKey": "X-CFF-Access-Key",
        "headerSecretKey ": "X-CFF-Secret-Key",
        "headerAuthToken": "X-CFF-Auth-Token",
        "headerSecurityToken": "X-CFF-Security-Token"
      },
      "serverEnvKey": {
        "runtimeProject": "RUNTIME_PROJECT_ID",
        "runtimeFuncName": "RUNTIME_FUNC_NAME",
        "runtimeFuncVersion ": "RUNTIME_FUNC_VERSION",
        "runtimePackage": "RUNTIME_PACKAGE",
        "runtimeTime": "RUNTIME_TIMEOUT",
        "runtimeHandler": "RUNTIME_HANDLER",
        "runtimeUserData": "RUNTIME_USERDATA",
        "runtimeCPU ": "RUNTIME_CPU",
        "runtimeMemory": "RUNTIME_MEMORY",
        "runtimeCodeRoot": "RUNTIME_CODE_ROOT",
        "runtimeApiAddr": "RUNTIME_API_ADDR"
      }
    }
    
2. 修改 Header，适配 functionGraph 响应表头
3. 适配 functionGraph 环境变量设置
