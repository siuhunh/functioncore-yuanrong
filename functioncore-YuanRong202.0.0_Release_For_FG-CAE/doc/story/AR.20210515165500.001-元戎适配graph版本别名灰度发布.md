# 元戎适配funcGraph版本、别名、灰度

关联AR：

1. AR.20210515165500.001：支持函数自定义版本号，兼容非数字模式 
2. AR-20210630-010-001 ：函数别名，灰度等支持 

## 1. Story整体设计

### 1. 功能描述
需求：
1. 对接functiongraph，支持用户自定义函数的版本号，实现非数字模式兼容；
2. 实现别名绑定和灰度发布。

### 2. 场景分析

时序图：

![](https://cloudmodelingapi.tools.huawei.com/cloudmodelingdrawiosvr/d/qhm?t=1624006315995)

​	在函数开发、测试、生产过程中发布一个或多个版本，实现对函数版本的管理。比如回滚等操作。
	函数别名的功能主要用于灰度发布，支持一个别名绑定两个函数版本，对两个版本进行权重分流。
	元戎涉及使用版本和别名的模块： 
 1. FuncAccessor：别名/版本，请求调度过来时的最初处理组件。在这个阶段会将urn解析成最终要执行的函数元信息的urn。Xxxx:版本/别名--->Xxxx:版本;
 2. BusProxy：别名和版本。也会涉及到和accessor一样的处理，校验逻辑一致，主要支持函数间调用逻辑。因为函数间调用不走accessor;
 3. FuncTask：functiontask这时候接收到的应该已经是处理过的函数调用信息了，只有函数版本，不涉及别名相关;
 4. FuncInstanceManager：别名和版本，到FuncInstanceManager的时候，此时携带的信息也是被处理过的了，他会进行一步校验，校验别名是不是为空，如果不为空的话是处理不了的;
 5. Worker/Runtime : 别名、版本。目前应该没有对别名和版本做日志打印，在worker初始化环境变量的时候，会将函数版本写进环境变量的；
 6. Repo：增加配置项，配置项打开，走graph校验逻辑，关闭则走元戎逻辑，不影响元戎的功能使用；
    别名下的灰度发布：
		别名的数据结构里面维护一个routerconfigs列表，每一个routerconfig里有版本urn和权重，此外还有一个负载均衡器，依赖这个负载均衡器去返回一个版本urn进入调用链传递到后续组件去执行。
		
### 3. 方案详细设计
​	按照当前的架构设计，函数版本、别名、灰度的增删改都是管理面组件进行，元戎需要做的是数据面进行对接，也就是函数调用请求过来的时候对函数urn进行校验，区分是版本号调用还是别名调用，随后将新的urn进行转发即可。 
	元戎和functiongraph对比： 

|                    |                             元戎                             |                          FuncGraph                           |
| :----------------: | :----------------------------------------------------------: | :----------------------------------------------------------: |
|        URN         |               7个字段，版本别名在最后一个字段                |                            同元戎                            |
| 版本、别名判断规则 | 最后一个字段进行校验，如果是$latest，或者能转为数字，那么认为是版本。否则，认为是别名。 | 最后一个字段进行校验，如果字段前面带有感叹号，认为是别名。否则，认为是版本号。 |
|      别名规则      | 支持小写字母开头，中间0到14位小写字母数字和中划线(-),  以小写字母或数字结尾; 别名长度最短2位，最长16位 |      字母开头，中划线，下划线,数字 结尾无限制，32位长度      |
|     版本号规则     |                        $latest或数字                         | 字母开头，支持字母中划线，下划线，点，数字，必须字母数字结尾，32位长度 |
​
具体方案：
1. 为了不影响元戎当前架构的功能实现，走全局配置FUNC_BRANCH，用于区分走元戎校验还是graph校验。
   校验规则：如果版本字段以!开头，那么认为是别名，做别名逻辑转发；否则就认为是版本，做版本逻辑转发。
2. FUNC_BRANCH规则:数字支持，默认为0，走元戎逻辑；1走funcGraph逻辑

### 4. 上下游依赖需求

​	只有accessor做别名或版本的逻辑校验，而后进行转发，无上下游相关依赖。
