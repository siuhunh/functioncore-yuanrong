# worker 容器保证证书安全

关联AR： 

        AR.SR.20210621221420.032.026: worker 容器保证证书安全
        
## 1. Story 整体设计
### 1.1 功能描述
   在满足安全需求的基础上，传递和使用证书秘钥等信息。
   
### 1.2 场景分析
目前通过 configmap 挂载给 worker container 的内容（以下简称安全配置）: 
- **对象存储的 ak/sk**   
  worker 初始化阶段连接，连接成功即可删除文件及内存信息
- **内部组件鉴权的 ak/sk**  
  worker 作为 bus server， 在 bus proxy 向 worker 建立连接后，使用其进行认证，考虑到 bus proxy 重启后需要向 worker 重新建立连接，重新认证，该加密信息将保留在内存中。
  与 function instance manager 鉴权。
- **function instance manager 鉴权以及解密 ak/sk 需要的秘钥（ functioncore 版本使用的 ddo\wdo）**  
  需要进行隔离，在部署配置中选择不提供该字段，functionGraph 版本配置中将不再体现该字段。
- **redis 的密码（金融场景使用）**   
  需要进行隔离，在部署配置中根据场景选择不提供该字段，functionGraph 版本配置中将不再体现该字段。
  
目前通过 secret 挂载给 worker container 的内容:
- **秘钥证书 （functionGraph版本使用）**  
    与内部组件鉴权时使用， 删除场景同 bus认证的 ak/sk
- **https证书 （functionGraph版本使用）**  
    与 code cache/worker manager 通信时使用， 加载函数（下载代码包）完成后可以删除。
  
因 configmap 的设计，容器对该文件只读， secret 同理，因此无法在使用结束后删除该文件，如被同 pod 中运行的用户函数攻破，获取到这些安全秘钥，有破坏系统的风险。
因此需要能够在使用完成后删除这些配置。

        【注】：worker container 如果退出， 该 pod 将会被删除，因此无需考虑文件被删除，无法再读取到的问题。

### 1.3 方案详细设计
   1. 将需要使用的安全配置（对象存储的 ak/sk ， 鉴权的 ak/sk ，秘钥证书，https 证书）通过 k8s secret 挂载到 init container 中， 在 init container 执行结束前拷贝到与 worker container 的共享目录下。
   2. worker 在读取完文件后，将文件从磁盘上删除，即部署阶段可见，用户函数运行阶段不可见。
    
### 1.5 上下游依赖需求
不涉及
