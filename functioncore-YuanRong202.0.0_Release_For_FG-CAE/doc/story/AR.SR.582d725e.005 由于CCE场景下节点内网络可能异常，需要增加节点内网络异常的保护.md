# 由于CCE场景下节点内网络可能异常，需要增加节点内网络异常的保护

## Story 整体设计

### 功能描述

#### 背景

https://dts-szv.clouddragon.huawei.com/DTSPortal/ticket/DTS2022062709329 【长稳-SDV-worker】乌兰202函数random_body_time 6月26号执行报函数错误6次，检查日志报错码是211503，请分析

该问题单根因是乌兰202上其中一个集群的一个节点网络异常，本机无法连通本机。节点重启后自动恢复。

对函数执行来说，出现211503后会重试，最终请求成功。但需要对该异常场景做兜底措施，防止因故障导致的服务不可用。

### 场景分析

需要考虑的场景：

1. 异常节点proxy连不上本节点的worker实例。
2. 实例的路由信息还存在，请求继续往异常节点的proxy转发，proxy每次请求都会扩容，会占用大量集群资源


### 方案详细设计

1. 缓存etcd中本节点的实例信息，定期对比（默认1分钟1次）缓存和workerevaluator，连续2次检测中缓存比workerevaluator多的实例，尝试缩容
