# snapshot-manager重制快照过程的日志观测

## 1. 需求场景分析

### 1.1 特性需求来源与价值概述

支持运维能够查看快照重制任务运行情况

主要包含1个AR：

* **AR.SR.IR20230331002207.001.003【functioncore】snapshot-manager重制快照过程中，日志观测**

*描述该特性的业务使用场景内容包括：*

1. runtime-java有变更的场景下，需要打印观测的日志
2. runtime-java无变更的场景下，打印无需重制重制快照

## 2. 特性/功能实现原理

### 2.1总体方案

##### 2.1.1.1 设计目标

**支持运维能够在LTS日志中查看快照重制任务运行情况**

##### 2.1.1.2 设计原理

启动重制快照Job后，拉起日志观测打印协程，该协程负责统计函数re-checkpoint时间，打印日志的总进度及时间，以及结束日志。
日志输出到**/var/paas/sys/log/cff/default/componentlogs/snapshot-manager-xxx/xxx.log路径，cffagent会采集并清理该路径日志并上传到LTS，通过LTS对日志进行观测。

### 2.2模块详细设计

*各模块的具体实现，包括模块的模块实现、对外接口定义、模块类设计*

1. runtime-java有变更的场景下，需要打印观测的日志
   (1）统计每一个快速启动函数的**re-checkpoint**时间
   (2）统计重制当前所有快速启动函数的进度，预估重制结束结束时间
   **重制快照进度 =  待重制函数数量 / 重制函数数量**
   **快照重制平均耗时 = （现在时间 - 任务开启时间）/ 已重制快照数量**
   **重制快照预估时间 =  待重制快照数量 * 重制快照平均耗时**
   (3）打印重制开始日志、打印结束重制快照日志和重制快照时间
2. runtime-java无变更的场景下，打印重制开始日志、打印无需重制快照、结束重制快照日志和重制快照时间
3.日志以ReCheckpoint| RUNTIME_MANAGER_Tag 格式开头。 例：2023-04-21 02:34:04.178 | INFO | checkpoint/checkpoint.go:816 | snapshot-manager-95rsv-5f6bq | cluster001 | ReCheckpoint| current snapshot java-runtime stays the same. skip re-do checkpoint
