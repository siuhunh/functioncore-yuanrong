# AR.SR.IR20230331002207.007.001 日志需要支持通过kafka转储

## 1. 需求场景分析

### 1.1 特性需求来源与价值概述

erp诉求，想将微服务的运维日志输出到kafka

### 1.2特性场景分析

javaruntime引入了log4j-core的maven依赖，而在log4j-core里面会可选的引入kafka-clients。

javaruntime当未用到kafka-clients时，打包时不会把kafka-clients的依赖也带上。

javaruntime加载用户函数时会使用javaruntime的自定义类加载器加载用户的kafka-clients。

由于java的类加载机制，在发送消息给kafka时使用的是系统类加载器，此时java会认为自定义类加载器加载的kafka-clients与系统类加载器需要的kafka-clients非相同的类，导致不可用。

## 2. 特性/功能实现原理

### 2.1  具体实现

1、通过将parent置为null来打破双亲委派模型

```java
public ExtClasspathLoader() {
    super(new URL[0], null);
}
```

2、对于用户入参传入的Context，原来可以通过双亲委派统一识别为AppClassLoad加载的类

当打破双亲委派机制后，runtime-java的Context为AppClassLoad加载，用户函数中的Context为ExtclassLoad加载，

此时若runtime-java生成Context实现类，传入用户执行函数，会报类不一致。

解决方案：将Context，PreRequestHandler等一系列用户函数要用到的类，打一个jar包，在自定义类加载器ExtClassLoader加载用户函数时，一并加载。

此后，我们都通过PreRequestHandler 这个中间类 使用反射间接执行用户函数中的代码。
