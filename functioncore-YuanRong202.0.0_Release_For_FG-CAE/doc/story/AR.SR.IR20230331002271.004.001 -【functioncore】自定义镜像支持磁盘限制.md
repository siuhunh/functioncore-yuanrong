# 【functioncore】自定义镜像支持磁盘限制

## 1. 需求场景分析

### 1.1 特性需求来源与价值概述

问题单转需求DTS2023032215102，自定义镜像函数当前没有对用户在容器中产生的数据做出限制，导致用户可以占用磁盘，进而导致磁盘爆掉。

### 1.2特性场景分析

针对以上情形，自定义容器函数worker会监控docker容器的创建，看到是自定义镜像的runtime容器，就用inotify监控磁盘大小，超过限制则用docker命令将它杀掉。

当前现在限制可以界面可以配置的512M和10G的大小。

### 2.1总体方案

根据欧拉系统不同，docker存储驱动不同，目前有devicemapper和overlay2两种。欧拉v2r5版本的docker存储驱动为devicemapper，欧拉v2r9版本的docker存储驱动为overlay2。

**devicemapper**：

`/var/lib/docker/devicemapper/mnt/[id]/rootfs` 下有容器完整的文件系统映射

id是docker inspect中DeviceName的最后一部分，即`b5a300a741409e762b7224f1b0f2a372574f7b16e12b972f7109b8a920feed52`，使用docker inspect命令可查

```bash
# docker inspect 0fb471b0886c
...
"GraphDriver": {
    "Data": {
        "DeviceId": "231545",
        "DeviceName": "docker-252:1-262145-b5a300a741409e762b7224f1b0f2a372574f7b16e12b972f7109b8a920feed52",
        "DeviceSize": "10737418240"
    },
    "Name": "devicemapper"
},
...
```

当有挂载磁盘时，在扫描判断rootfs大小时，需要排除挂载路径上的文件大小。

监控该runtime容器对应的rootfs的新增的内容大于限制大小，则调用docker命令杀掉它。

**overlay2**：

**docker inspect --size containerID -f '{{ .SizeRootfs }}'**

获取到当前容器中所有文件的总大小，当有文件写入时，SizeRootfs会增加，当达到限制的时，直接杀掉runtime容器。

当有挂载磁盘时，在挂载磁盘的路径下写入文件，docker inspect 获取到的 sizeRootfs的大小不发生变化，所以不用排除挂载路径上的文件大小。

大于限制的话 直接采用kill runtime容器。

**当前限制：**

大于限制的直接调用docker 命令kill 掉runtime 容器，返回一个磁盘超限的错误。
