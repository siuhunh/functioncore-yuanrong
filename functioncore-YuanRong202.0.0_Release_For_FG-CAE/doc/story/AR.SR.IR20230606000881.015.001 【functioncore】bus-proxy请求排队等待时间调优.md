# AR.SR.IR20230606000881.015.001 【functioncore】bus-proxy请求排队等待时间调优

## 1. 需求场景分析

场景：由于APIG 60S超时规格限制，达到最大实例时，busproxy排队的消息等待40s后再返回到rdispatcher重试，只能重试1次且20s不能返回就会报错，存在可靠性风险

### 1.1 特性需求来源与价值概述

需求来源：在丰田压测和智利vessi压测过程中，当集群资源不足或达到用户/函数的最大实例数时，均会在bus的请求队列中等待40s之后才会返回请求异常

价值概述：固定40s的等待时间在当前看来并不完全合理，需要进行优化，并单独考虑资源不足或到达最大实例数的场景

### 1.2特性场景分析

1、当函数请求由frontend发送至bus-proxy时，bus-proxy会为每一个函数创建一个请求队列，并在队列初始化时指定超时时间为40s
2、当bus-proxy发现自己没有纳管的实例进行请求处理，或当前纳管的实例已经满负荷处理请求，会根据弹性算法向worker-manager申请实例（扩容）
3、若worker-manager返回正常特化后的实例，如果此实例与bus-proxy在同一节点，则bus-proxy会将请求下发进行处理，若不在同一节点（远端worker）则会将请求反压
4、若worker-manager返回异常，如果当前bus-proxy已经有纳管的实例、返回的错误为获取实例异常、返回的错误为到达最大实例上限且正在扩容的实例数量不为0时，则会将请求重新放回请求队列
5、若worker-manager返回异常，如果返回的异常为函数元数据信息不存在，则会立刻返回异常
6、重新放回请求队列中的请求，会按之前的执行逻辑，继续触发扩容请求或被下发执行，直到达到40s的超时时间

## 2. 特性/功能实现原理

1、队列初始化时指定超时时间40s不变（bus-proxy尚未纳管对应函数的实例）

2. bus-proxy已经有纳管的实例时，超时时间调整为20s（支持热加载可配置）

3. 对于到达最大实例数上限的错误（函数150429/租户最大实例150432），超时时间调整为10s（支持热加载可配置）

"autoScalerConfig": {
    "withInstanceQueueTimeout": 25,
    "maxInstanceQueueTimeout": 15
}
