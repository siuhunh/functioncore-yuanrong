# AR.SR.IR20230824003700.027.001 【服务依赖】路由ETCD故障不影响函数冷启弹性

## 1. 需求场景分析

场景：当前路由ETCD故障，worker-manager完成实例特化后，无法正常将实例信息写入，若存在远端实例的情况，对应bus-proxy无法感知并纳管

### 1.1 特性需求来源与价值概述

需求来源：服务依赖降级场景下，外部依赖故障，业务组件不能主动退出，且需要保证函数基本调用功能正常

价值概述：系统可靠/可用/韧性加固，保证在路由ETCD异常时，业务组件不发生重启，且能够持续上报异常的告警，且能正确纳管实例

### 1.2特性场景分析

1、当前bus-proxy感知并纳管实例主要有两种方式，向worker-manager申请实例时从返回结果获取，或者监听路由ETCD感知
2、worker-manager完成实例特化后会将实例信息写入路由ETCD，此流程非阻塞，写入失败不影响结果返回
3、若worker-manager返回的实例，与发送扩容请求的bus-proxy在同一节点，则会直接进行纳管
4、若worker-manager返回的实例，与发送扩容请求的bus-proxy不在同一节点，则会触发请求反压，经由frontend将请求转发给对端bus-proxy
5、此时由于路由ETCD故障，对端bus-proxy未感知新实例，反压请求发送过来时，会再次触发扩容，产生多扩的情况
6、备worker-manager在路由ETCD异常时，存在异常重启的问题，也需要一并进行修正

## 2. 特性/功能实现原理

方案一. 若worker-manager返回远端worker，则bus-proxy直接通知远端worker所在的bus-proxy进行纳管
    1. 当bus-proxy决策需要进行弹性扩容时，调用worker-manager的扩容接口：
    instance := das.scaleUp(traceID, currentWorkerNum, scalingWorkerNum, isRetry)
    2. 对返回的实例进行纳管：
    err := das.workerScaledUp(instance)
    3. 若感知到实例是远端worker，则通知远端bus-proxy
    NotifyRemote(remoteIP string, dst *common.FunctionProperty, event *common.NotifyEvent) error
    
方案二. 若worker-manager返回远端worker，则bus-proxy通过请求反压，由frontend将远端worker实例信息转发至对应bus-proxy：
    1. 当bus-proxy决策需要进行弹性扩容时，调用worker-manager的扩容接口：
    instance := das.scaleUp(traceID, currentWorkerNum, scalingWorkerNum, isRetry)
    2. 对返回的实例进行纳管：
    err := das.workerScaledUp(instance)
    3. 若感知到实例是远端worker，则通过反压将信息传递至frontend，由frontend将实例信息转发至对端bus并进行纳管
    das.addToBackPressureInstance(instance)
    das.backPressureRequests(position, true, 0)

由于worker-manager集群健康检查接口会对路由ETCD的连通性进行校验，当路由ETCD故障时，集群健康检查接口会返回错误，当前备worker-manager与主worker-manager之间的心跳涉及此接口调用
当接口返回路由ETCD故障的返回信息，而非超时等信息时，备worker-manager不再进行重启

### 2.3 约束

1、由于纳管动作出现在冷启动阶段，为了保证纳管日志不会刷屏，新增的日志会以debug日志级别打印
2、由于当前主worker-manager通过注册方式由bus-proxy感知，因此请求不会再通过备worker-manager转发的方式传递至主worker-manager，不重启不会产生影响
