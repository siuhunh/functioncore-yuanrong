# 【有状态函数】【可靠性】bus异常场景，保证有状态函数正常运行

## 1. 需求场景分析

### 1.1 特性需求来源与价值概述

增强异常场景下，有状态实例、状态路由数据的准确性

### 1.2特性场景分析

1、优化当前worker-manager初始化重新拉起有状态实例未进行集群校验的问题
2、优化state-manager进行路由迁移时未保留共池版本新增字段的问题

### 2.1总体方案

### 2.2模块详细设计

1、当前worker-manager已有功能逻辑：

- 创建状态路由拉起有状态实例后，确保状态路由存在，把worker-manager实例数改为0，删除此有状态实例
- 恢复worker-manager实例数量后，能够根据状态路由重新拉起有状态实例

存在的问题：
- 在进行有状态实例重新拉起的判断决策时，未考虑状态路由的集群归属情况，若2个集群的worker-manager同时触发此重启场景，则会重新拉起两个实例

优化方案：
- 创建/更新状态路由时，向value中写入集群ID信息
- worker-manager在进行重新拉起实例校验时，进行集群校验，状态路由与自己所在集群一致，才会触发实例拉起，否则不会触发

兼容性问题：
- 旧版本的状态路由中不存在集群ID信息，则在进行校验时默认不触发重新拉起，由调用请求触发

2、当前state-manager已有功能逻辑：

- state-manager感知到functiontask的下线动作，会重新触发状态路由的分配

存在的问题：
- 在进行状态路由重新分配时，未将最近迭代新增的value内容恢复，导致以下新增字段缺失
  creatorKey     = "creator"
  tenantIDKey    = "tenantID"
  businessIDKey  = "businessID"
  serviceIDKey   = "serviceID"
  versionKey     = "version"
  funcNameKey    = "funcName"

优化方案：
- 重新分配状态路由时，除更新节点信息外，其余信息保持原状写入

兼容性问题：
- 旧版本的状态路由中不存在新增信息，保持不变
