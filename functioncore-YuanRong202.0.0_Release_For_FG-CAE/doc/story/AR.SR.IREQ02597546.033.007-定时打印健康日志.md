# AR.SR.IREQ02597546.033.007-定时打印健康日志

## 1. Story 整体设计
### 1.1 功能描述
当前cff-agent会定时清理日志，当一个日志文件12小时没有新日志写入时就会认为已经是废弃的文件，会被清理，元戎日志可能因为容器的闲置状态被清理掉，导致丢失必要定位日志。 <br>
因此定时打印各容器的健康日志，打印已有的必要信息，防止日志被误清理，也方便开发定位时了解组件在什么时间是健康的。

### 1.2 场景分析
1. 打印的日志内容均为内存中已有的信息，不因为此需求新增内存中维护的内容
2. 所有输出数据不加锁，保证不影响性能，数据5分钟一次，可能有误差，一直变化的数据不要求精准
3. 组件启动5分钟后打印第一次，之后每5分钟打印一次

### 1.3 方案详细设计
- **健康日志格式** <br>
以frontend举例：<br>
  frontend is alive. The number of connected nodes is %d

- **健康日志提供的信息** <br/>

  | 组件名 | 提供信息 |
    | ------------ | ------------ |
  | frontend | 连接的node数量 |
  | busproxy(functiontask) | 自己为owner的pod数量、当前处理请求数 |
  | worker-manager | 已特化的池子数量、未特化的池子数量 |
  | worker | runtime实时内存的监控、worker和bus是否连通 |
  | runtime-manager | 是否特化、未特化时打印当前runtime list、已特化时打印当前runtime类型和版本 |
  | cache-manager | 本地缓存的函数包数量 |
  | workflow | 自己是否为主、为主的打印自己维护的workflow数量、当前workflow容器里面跑了多少个任务 |

### 1.4 上下游依赖需求
cffagent在此功能上线后不误清理元戎组件日志，正常清理无用日志文件。对接人潘炜程
