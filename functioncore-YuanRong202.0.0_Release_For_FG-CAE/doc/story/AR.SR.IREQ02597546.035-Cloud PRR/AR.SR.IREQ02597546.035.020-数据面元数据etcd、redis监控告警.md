# AR.SR.IREQ02597546.035.020-路由etcd、redis监控告警

## 1. Story 整体设计

### 1.1 功能描述

路由etcd和redis需要监控关键信息，能够在出现问题时告警

### 1.2 场景分析

为了监控数据库的状态，etcd和redis在有关键指标超限的情况下应该告警

### 1.3 方案详细设计

- **etcd监控方式** <br/>
配置CCE集群中AOM方式告警，过滤方式设置appName为etcd

| 名称 | 告警级别 | 设置 |
| ---- | --------------- | ------------------  |
|  FunctionGraph数据面etcd严重告警 | 紧急 | 监控磁盘占用大于80%，1次即告警；监控CPU使用率或内存使用率大于95%，5次即告警 |
|  FunctionGraph数据面etcd状态告警 | 严重 | 监控etcd容器pod状态，1次即告警 |
|  FunctionGraph数据面etcd重要告警 | 严重 | 监控CPU使用率，连续5次即告警；内存使用率大于85%，连续5次即告警 |

【etcd容器日志采集】 : 日志输出在节点目录 /var/log/pods/default_ds-core-etcd-0_31611b3f-bd31-4ba8-a8e5-dd3b7b6c837e/etcd/， CFF进行日志采集

- **redis监控方式** <br/>
使用DCS的监控告警，【对接CES】
  
| 名称 | 告警级别 | 设置 |
| ---- | --------------- | ------------------  |
|  FunctionGraph数据面redis严重告警 | 紧急 | 监控磁盘占用大于80%，1次即告警；监控CPU使用率或内存使用率大于95%，5次即告警 |
|  FunctionGraph数据面redis重要告警 | 严重 | 监控CPU使用率，连续5次即告警；内存使用率大于85%，连续5次即告警 |

- **Node监控** <br/>
  在CloudScope中配置告警规则如下：(etcd节点在数据面集群中，已经统一配置)

| 告警名称 | 告警级别 | 设置规则 |
| ---- | --------------- | ------------------  |
|  FunctionGraph数据面节点CPU95%告警 | 重要 | 监控各节点CPU使用率，连续5次超过95%即告警 |
|  FunctionGraph数据面节点内存95%告警 | 重要 | 监控各节点内存使用率，连续5次超过95%即告警 |
|  FunctionGraph数据面节点磁盘80%告警 | 重要 | 监控节点磁盘使用率，1次超过80%即告警 |

- **告警级别** <br/>

| 级别 |     告警方式           |
| ---- | ------------------ |
| 紧急   | oncall人员收到电话，在cloudscope配置的组内所有人员收到短信 |
| 严重   | oncall人员收到短信 |
| 提示   | 系统记录 |

### 1.4 上下游依赖需求
与cloud scope管理人员对接，添加设计好的告警。对接人施广帅
