# 预留实例和普通实例调度策略

关联AR:
+ ARID: AR.SR.IREQ02597546.039.001 

## Story 整体设计

### 功能描述
* 将发往每个BusProxy的请求优先调度到预留实例，预留实例请求满后，再触发扩容，调度普通实例。

### 场景分析
预留实例和普通实例计费规则不同，有预留实例的场景应该优先调度请求到预留实例上面。只有当并发能力不够触发扩容时，才调度普通实例。


### 方案详细设计

#### 现状分析
当前调度策略，不区分预留实例和普通实例。

优先级计算公式：

> value = PriorityRate * (requestNums / concurrency)

存在问题：

> * requsetNums < concurrency ，导致优先级计算永远为0，优先级失效。
> * 计算不区分预留实例和普通实例，都会去进行调度，导致触发普通实例扩容后无法进行缩容。

#### 方案设计

1. 实例调度策略：

> * 从实例队列依次"打满"实例，实例队列依据优先级进行排序。

![BusProxy实例调度](https://cloudmodelingapi.tools.huawei.com/cloudmodelingdrawiosvr/d/1HKb?t=1638758889992)

2. 优先级设计：

> * 实例优先级设计为三级：预留实例 >> 本地普通实例 >>  远端普通实例
>
> * PriorityRate 设计：(权重)
>
>   * 远端实例：0
>
>   * 本地实例：100
>
>   * 预留实例：200
>
> * 优先级计算公式：
>
>   value = priorityRate + requestNums

3. 实例队列需要区分是普通实例还是预留实例：

> * BusProxy 实例订阅事件，如果订阅到预留实例时，刷新到实例队列，供优先级计算和实例调度。

### 约束
当前方案存在如下约束：

1. 预留实例所在节点的BusProxy正在升级或重启中，请求发过来之后会重试到其他proxy，触发普通实例的扩容，当前无法管理。
2. frontend轮训调度。若有两个预留实例，分别部署在A，B节点。此时有过多请求将两个预留实例都给打满，触发普通实例扩容，由于调度是轮训随机的，可能会在两个节点都拉起普通实例。
