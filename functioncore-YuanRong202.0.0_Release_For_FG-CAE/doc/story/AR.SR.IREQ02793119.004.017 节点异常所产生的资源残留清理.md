# AR.SR.IREQ02793119.004.017 节点异常所产生的资源残留清理

## 1. 需求场景分析

### 1.1 特性需求来源与价值概述

需求来源于问题单DTS2022083002962转需求 该问题是CCE本身的问题，非产品问题，且各种现象均有对应的官方文档做合理解释，但是对于节点异常后部分Pod处于Teminating状态资源残留，需要安排专项需求进行资源清理。

问题单：https://dts-szv.clouddragon.huawei.com/DTSPortal/ticket/DTS2022083002962

CCE文档：https://support.huaweicloud.com/cce_faq/cce_faq_00210.html

### 1.2特性场景分析

1、在节点处于“不可用”状态时，CCE会迁移节点上的容器实例，并将节点上运行的pod置为**“Terminating”**状态。待节点恢复后，处于**“Terminating”**状态的pod会自动删除。偶现部分pod（实例）一直处于**“Terminating ”**状态，持续占用资源。

2、现在预留实例如果碰这种情况，会导致预留实例处于Terminating状态，虽然用户任然可以拉起正确的预留实例个数，但是遗留的Terminating状态的预留实例会没5分钟进行计费上报会导致用户可能被多收费。

## 2. 特性/功能实现原理

### 2.1总体方案

1、worker优雅退出超时时间为12小时，超时的会自动被删除，仍然存在的Terminating的pod即为无法退出，需要强删pod。

配置pod Terminating持续时间大于多少时删除，有事件进来的时候记录一下时间和Terminating pod，定期对仍在terminating的pod进行强删

2、对于遗留的Terminating状态的预留实例多计费的问题，Terminating状态的预留实例仍然会进行计费，在重新连上节点后会上报计费，而bus无法识别节点是否不可用，没有什么好的方案，讨论由管理面解决：预留实例由管理面判断实例个数，计费上报实例不多于最大实例个数。作为预留实例多计费兜底方案
