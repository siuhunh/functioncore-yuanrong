# AR.SR.IREQa2b7bf96.003.014 特化失败场景限制

## 1. 需求场景分析

前提须知：普通函数特化失败会被当做特化成功处理。

当前需求场景：自定义镜像特化失败的场景。例如：自定义镜像函数 Init() 执行失败。

### 1.1 特性需求来源与价值概述

- 现网出现自定义镜像特化失败，频繁消耗资源。

### 1.2特性场景分析

*描述该特性的业务使用场景内容包括：*

（1）场景触发条件：自定义镜像函数，Init() 执行失败；

（2）关键任务操作：

a. 连续三次特化失败，触发熔断；
b. 10s 内执行该函数的特化请求；
c. 10s 后有 20% 的特化请求被执行；
d. 失败则触发熔断，继续执行操作步骤 b；
e. 成功则关闭熔断，允许所有特化请求通过；

## 2. 特性/功能实现原理

### 2.1  总体方案

设计接口如下：
```go
type Breaker interface {  
   Fail()  
   Succeed()  
   IsAllowed() bool  
}
```

[特化失败场景限制-Open Model](https://cloudmodeling.tools.huawei.com/projectspace/detail/2928afd8ae624e609af7b0148bf05fad?projectDiagramUUID=c7c72f2b74364407a1e06d6337cc9916&versionUUID=)![特化失败场景限制](https://cloudmodelingapi.tools.huawei.com/cloudmodelingdrawiosvr/d/3PYP?t=1676275401366)
a. worker-manager 收到特化请求后，会调用 IsAllowed 方法判断此次特化请求是否允许被执行；
b. 如果 10s 内连续三次特化失败，则对这个函数开启熔断器，后续 10s 内的特化请求会被拒绝； 
c. 10s 后熔断器处于半开状态，允许部分特化请求通过；（当前设置的是 20% 可配）
d. 此处的特化请求属于探测流量，如果此次特化请求执行成功，则熔断器关闭，解除限制；执行失败，则熔断器开启，开启限制；

熔断器配置如下：
```go
type Rule struct {  
   TimeWindow          int     `json:"timeWindow"`  
   MaxConsecutiveFails int     `json:"maxConsecutiveFails"`  
   MaxAllowedFails     int     `json:"maxAllowedFails"`  
   CoolingTimeout      int     `json:"coolingTimeout"`  
   HalfOpenPassRate    float64 `json:"halfOpenPassRate"`  
}
```

默认配置如下：
```go
defaultRuleConfig = &Rule{  
   TimeWindow:          10,  
   MaxConsecutiveFails: 3,  
   MaxAllowedFails:     10,  
   CoolingTimeout:      10,  
   HalfOpenPassRate:    0.2,  
}
```

特化请求限制的返回错误码和错误信息：

```go
// TooManySpecializedFails marked that there are too many specialized fails
var	TooManySpecializedFails = 150437
TooManySpecializedFails:     "too many specialized fails",  
```
