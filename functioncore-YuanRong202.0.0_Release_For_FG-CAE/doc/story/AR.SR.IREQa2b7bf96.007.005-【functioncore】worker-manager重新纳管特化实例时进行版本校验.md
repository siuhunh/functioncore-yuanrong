# AR.SR.IREQa2b7bf96.007.005-【functioncore】worker-manager重新纳管特化实例时进行版本校验

## 1. 需求场景分析

### 1.1 特性需求来源与价值概述

来源：现网发现，反馈需求

价值：可以保证升级后用户实例在异常场景下也能使用最新版本

### 1.2特性场景分析

1. 客户的函数实例在每次版本升级时需要优雅退出升级重拉，保证最新版本的特性和bugfix对所有客户生效
2. 之前在现网曾发生过，当缩容有bug无法正常缩掉用户实例/切流未把预留实例切出时，会导致有老版本客户实例一直被使用，新版本的特性和bugfix不生效的情况

## 2. 特性/功能实现原理

### 2.1总体方案

worker-manager启动时遍历全部用户实例检查镜像tag，有老版本的则删除实例pod让其优雅退出

### 2.2模块详细设计

*各模块的具体实现，包括模块的模块实现、对外接口定义、模块类设计*

在worker-manager启动初始化时，纳管函数实例会对所有pod对象进行一次遍历，检查其中的容器镜像tag是否和worker-manager中配置的版本号一致
1. 自定义镜像
   自定义镜像检查worker和worker-init两个容器的镜像tag

2. 其他类型函数
   其他类型的函数实例检查worker、runtime-manager、worker-init三个容器的镜像tag

### 2.3 约束

#### 2.3.1上下游依赖需求

不涉及

#### 2.3.2其他约束

1. 此功能只对用户实例生效，如果有池子pod升级未退出为K8s（CCE）问题，不在此需求范围内
