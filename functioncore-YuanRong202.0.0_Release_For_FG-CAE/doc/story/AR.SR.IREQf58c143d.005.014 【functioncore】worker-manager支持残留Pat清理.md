# AR.SR.IREQf58c143d.005.014 【functioncore】worker-manager支持残留 Pat 清理

## 1. 需求场景分析

1. 在函数特化实例时，vpc 插件优先返回了一个 pat pod，后台再默默创建并初始化第二个 pat pod；
2. 由于后续没有新的实例特化请求，所以第二个 pat pod 没有给到 worker-manager；
3. worker-manager 没有感知到第二个 pat pod，所以没有执行清理的动作；

### 1.1 特性需求来源与价值概述

- 针对第二个 pat pod 创建后没有被使用而导致残留的问题，增加清理机制

### 1.2特性场景分析

*描述该特性的业务使用场景内容包括：*

函数特化实例，vpc controller 先返回第一个 pat；后续没有新的实例请求，初始化好的第二个 pat 残留；

**出现概率：**
- 当用户只用了一个 vpc 函数实例，会出现这样的残留； 
- 用户在第二个 pat 初始化期间，拉起了多个 vpc 函数实例，在第二个 pat 初始化好了之后，没有拉起函数实例，也会出现这样的残留；

## 2. 特性/功能实现原理

### 2.1 特性

- 第二个 pat 初始化完成后，vpc 插件通知 worker-manager；
- 由 worker-manager 通知所有的 worker；
- worker 将第二个 pat 记录到缓存中，作为备用 pat；
