# AR.SR.d5193e1e.002【functioncore】funcInstMgr 实时校正路由数据和 cr 数据

AR：AR.SR.d5193e1e.002

## 1. Story 整体设计

### 1.1 功能描述

- 背景：路由 etcd，function cr 需要考虑因第三方异常导致更新失败，数据不一致的问题【可靠性增强】

- **存在的问题**：
  - 路由 etcd 的更新、cr 更新虽然有重试操作，但没有考虑 etcd 故障场景；
  - 函数发生变化，正在重试中的操作不会被取消；



### 1.2 方案详细设计

**整体方案**

- 针对*路由 etcd 的更新、cr 更新虽然有重试操作，但没有考虑 etcd 故障场景*：
  - 更改重试的方式，在操作内重试
  - 记录重试后失败的操作，在路由 etcd 健康时，恢复数据
- 针对*函数发生变化，正在重试中的操作不会被取消的场景*：
  - 引入 context 来控制正在执行的操作，保证当函数更新或删除后，正在执行的操作能够及时停止



**1. 路由 etcd 更新时网络抖动场景：（重试）**

- 网络抖动导致的操作失败，通过重试的方式保证更新成功
- 重试 10 次，每次间隔 20 ms



**2. cr 更新失败场景：（重试）**

- 通过重试的方式保证更新成功
- 重试 10 次，每次间隔 20 ms



**3. 路由 etcd 故障场景：**

- 记录**重试后**操作路由 etcd 失败的 key、value、操作类型（Put、Del）
- 路由 etcd 健康检查成功时，重新执行失败的 key，从路由 etcd 写入或删除 key
- 对于同一个 key，后一个失败的操作，覆盖前一个失败的操作（对一个 key 的操作以最后一次为准）
- TODO：失败次数超过 100



**数据结构：**

```go
type ETCDOperation struct {
    value []byte
    operate string // 枚举 put del
}

FailedOperations map[string]*ETCDOperation
```
