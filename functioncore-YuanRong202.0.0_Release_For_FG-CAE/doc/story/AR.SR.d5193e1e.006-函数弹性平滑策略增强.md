# 函数弹性平滑策略增强

### 功能描述

函数的弹性策略结合函数实例吞吐率，扩容速率等综合计算，选择最优的实例配比，降低系统和用户的成本，满足80wQPS，函数实例数量 < 1000。

### 方案详细设计

#### 现状分析

当前的弹性算法：

  		scaleNum = ceil ( waitedReqNum / funcConcurrency )

在请求流量突增时，迅速扩容满足这些请求运行的实例个数，而因为扩容的速度往往十倍百倍于请求的处理速度，导致大量扩容的实例浪费，系统的成本极高。

#### 方案设计

优化算法：

结合 tpsPerWorker，currentWorkers，scalingWorkers，ScaleLatency （池化/非池化）多维度计算所需扩容数量。在请求量突增时，函数的弹性策略为先快后慢，弹性自适应策略设置一个生效阈值。

示例：

		scaleNum = ( waitedReqNum - (tpsPerWorker * currentWorkers + tpsPerWorker * 系数 * scalingWorkers ) * avgScaleLatency ) / 系数 * tpsPerWorker



```
【注】：压力测试前函数需要设置合理的并发度和规格；支持io密集型，cpu密集型等函数，不考虑类似sleep随机的函数
```

## 可信软件

#### 安全性 Security
*系统对恶意威胁的防护能力。可能的威胁包括但不限于未授权访问、使用、泄露、破坏、修改、毁灭；防护目标是保持信息的机密性、完整性和可用性*  

#### 韧性 Resilience
*系统受攻击时保持在有定义的运行状态（包括降级）、遭遇攻击时快速恢复核心系统、受攻击后在业务需要的时间窗内恢复到有效运行态*  

#### 隐私性 Privacy
*系统具备能力能使客户（含组织和个人）能够就收集、使用、保有、披露和处置个人信息履行其权利和义务*  

#### 可靠性 Reliability
*在给定的条件、给定的时间区间能无失效地执行要求的能力*  

#### 可用性 Availability
*处于按要求执行状态的能力*  

#### 安全 Safety
*系统失效导致的危害不存在不可接受的风险，不会伤害自然人生命或危及自然人健康，不管是直接还是通过损害环境或财产间接造成的*
