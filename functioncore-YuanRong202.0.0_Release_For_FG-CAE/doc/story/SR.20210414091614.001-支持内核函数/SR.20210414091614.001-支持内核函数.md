## Story 整体设计

### 功能描述
​    FunctionCore对普通用户来说，屏蔽了后台资源信息，为开发者提供的开发环境主要是以上层业务为主，因此函数平台不适合用于系统开发者使用，计算平台需要扩展业务功能并不能使用普通函数来进行开发，鉴于此，引入了内核函数的概念，系统管理者可以使用内核函数来进行本身系统能力的快速扩展。

​    当FunctionCore平台需要扩展一些系统级能力的时候，比如函数调度时具有自定义亲和性能力。系统管理员可以开发普通函数的方式来开发系统能力，并发布到FunctionCore平台上。

​    内核函数由于能访问FunctionCore的系统资源，需要增强对权限上进行管理，否则普通用户也去尝试着开发内核函数，将会引来灾难性的后果。



### 场景分析
函数实例亲和性：为了系统安全稳定考虑，开发者无法感知函数实例的资源信息比如节点位置信息、ip信息等，某些函数实例需要运行在特定的节点上以保证有更高的性能，函数运行的亲和性和反亲和性。

函数之间互通：对于一些特性的场景，比如大数据计算等，强依赖系统内的ip点对点通信，由于函数平台默认不感知内IP，函数平台无法有效支撑这类业务




### 方案详细设计

#### 现状分析
AWS Lambda Intrinsic function 

AWS Lambda提供了一个intrinsic function的特性，由系统预置了一系列常用的函数，方便开发者构建自己应用时直接使用，不需要开发者单独进行开发 。但还是不具有与平台进行进行交互的能力，无法使用函数平台的能力来进行扩展。

PI1 转测SR澄清

1、函数预置功能因人力可能会转测滞后，概要设计已有说明。

2、kernel-runtime复用的c++ runtime，而且kernel-worker/kernel-runtime不会退，runtime每次加载不同函数会覆盖，暂不支持符号卸载特性，runtime可能存在内存泄漏问题，另外同名函数加载到同一个kernel-worker不会进行覆盖 。

3、worker与runtime之间的链路未做可靠性，存在低概率的断链导致函数调不通的情况。

4、目前仅支持基础功能转测，暂不支持异常、并发等可靠性测试，比如将组件去人为挂掉重启 。

5、内核函数调普通函数/租户信息记录  未实现

## 可信软件

#### 安全性 Security
*系统对恶意威胁的防护能力。可能的威胁包括但不限于未授权访问、使用、泄露、破坏、修改、毁灭；防护目标是保持信息的机密性、完整性和可用性* 

#### 韧性 Resilience
*系统受攻击时保持在有定义的运行状态（包括降级）、遭遇攻击时快速恢复核心系统、受攻击后在业务需要的时间窗内恢复到有效运行态* 

#### 隐私性 Privacy
*系统具备能力能使客户（含组织和个人）能够就收集、使用、保有、披露和处置个人信息履行其权利和义务* 

#### 可靠性 Reliability
*在给定的条件、给定的时间区间能无失效地执行要求的能力*

#### 可用性 Availability
*处于按要求执行状态的能力*

#### 安全 Safety
*系统失效导致的危害不存在不可接受的风险，不会伤害自然人生命或危及自然人健康，不管是直接还是通过损害环境或财产间接造成的*
