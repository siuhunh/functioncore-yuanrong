## FunctionAccessor支持升级策略 



## 1. Story整体设计



### 1. 功能描述

**背景:**

为了保障在现网环境升级时，FunctionAccessor业务不中断，请求不丢失且被正确处理完毕。

**需求:**

1. 滚动升级，控制按批次升级，避免在升级过程中业务中断。
2. 优雅退出，去捕获停止信号，不立即进行中断退出，等所有现有请求处理完成后才退出。同时可设置超时时间，超时时间过了未完成退出则强制退出。
3. 收到升级请求后，确保不会有新的请求再进来。



### 2. 场景分析



### 3.方案详细设计

**1. 滚动升级**

可以在frontend-deployment.yaml中配置FunctionAccessor的更新策略：

```yaml
terminationGracePeriodSeconds: {{ .Values.global.timeout }}
replicas: {{ .Values.global.replicas.frontend  }}
rollingUpdate:
      maxSurge: 25%
      maxUnavailable: 25%
    type: RollingUpdate
```

- terminationGracePeriodSeconds：
  - 超时时间，k8s向pod发送SIGTERM信号后，过了超时时间pod还没退出，会发送SIGKILL信号，强制pod退出。当前为900s， 与最长的函数调用超时时间保持一致。
- replicas:
  - 副本数
- maxSurge:
  - 和期望ready的副本数比，超过期望副本数最大比例（或最大值），这个值调的越大，副本更新速度越快。向上取整 
- maxSurge:
  - 和期望ready的副本数比，不可用副本数最大比例（或最大值），这个值越小，越能保证服务稳定，更新越平滑。向下取整。 



**2. 优雅退出**

1. 启动协程监听k8s SIGTERM 和 SIGKILL 信号。
2. 创建一个计数器，用WaitGroup实现。当有一个请求来时，计数器+1，当请求结束返回后，计数器-1。只有当计数器等于0，表示所有请求已处理完毕。
3. 当监听到SIGTERM信号后，启动优雅退出。调用WaitGroup的Wait方法，等所有消息处理完成后，再退出组件。
4. 如果超时时间到了组件还没退出，这时会监听到SIGKILL信号，这时候就强制退出组件。



**3.老版本pod退出时不接收请求**

​	为了能让优雅退出顺利进行，老版本pod退出时不能接收新请求。这点能通过k8s滚动升级机制保证。当k8s向老版本pod发送SIGTERM信号，告知pod自动退出后，k8s会把该pod设置为Remove状态，这是所有请求都不会发送给该pod。
