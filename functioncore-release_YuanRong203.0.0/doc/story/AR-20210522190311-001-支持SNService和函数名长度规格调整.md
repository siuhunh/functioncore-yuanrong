# 支持SNService和函数名长度规格调整


## 1. Story 整体设计
### 1.1 功能描述
FunctionGraph  与 yuanrong 函数名，package，handler 存在较大差异，详细见下边场景分析表格，yuanrong需要兼容FunctionGraph 的函数名称等问题
### 1.2 场景分析
#### 差异对比表

#### 差异引入的问题

- FunctionGraph  package(serviceID)长度是 **60**，函数名程长度是**60** ，这样就会导致，yuanrong的函数名长度需要兼容到124，但是我们存在正则校验（长度51）
- FunctionGraph  package(serviceID) 中存在中划线，但是yuanrong中是使用中划线来分割serviceID跟functionname，如果兼容，则在解析的地方无法分割出serviceID
- K8S标签长度是63 位，yuanrong因为使用了自定义资源（functionservice）,使用ownerreference 来删除pod，在Cr中函数名称长度超过了label（63）标签
    
    *使用自定义资源（functionservice）的说明：*
    - 快速查询
    - worker继承owner的label


### 1.3 方案详细设计
**主旨：**
- 运行面兼容FunctionGraph 的函数定义，yuanrong管理面的约束保持不变，即黄区环境创建函数规则不变
因此 函数名存在以下两种形式：如果函数名包含@，则按照2解析
    - **0-serviceID-functionName**
    - **0@serviceID@functionName**

**约束：**
- 函数名：

长度（63）  可包含数字（不可在开头），字母（大小写都支持），下划线（不可在开头），中划线（不可在开头），
- serviceID：

长度（63）  可包含数字（不可在开头），字母（大小写都支持），下划线（不可在开头），中划线（不可在开头）
- serviceID与函数名分割符：

替换掉函数名与serviceID的分隔符，替换为@，yuanrong管理面保持不变， 运行面兼容以@符号分割的函数名，解析出serviceID
- ***FunctionGraph 在往ETCD中写数据的时候，以@分割 package与functionname，格式如下 0@package@functionname （对接FG调用责任人：刘方凯）***

**修改点：**

- instanceManager在创建CR的时候，ID截取functionname的部分字段+随机数，标签写入 functionname，serviceID(新增字段)，TenantID,version
ID ，此处规则跟之前保持不变，尽量能展示出函数名信息
- 去掉数据面组件（除functionAccessor）关于函数名，serviceID的校验
- 其余组件兼容简单分析如下：有部分组件中涉及到拼接functionName,此部分组件需要根据第8条来决定使用的分隔符，
- FunctionGraph  runtime sdk context 有从urn解析package functionname 的接口，因为此部分功能不涉及黄区内容，因此解析分隔符直接使用@

|  frontend-invoke  |  解析serviceID  |
|:---|:---|
|  cosdk  |  解析  |
|  bus  |  解析  |
|  workermgr  |  解析 拼接 写标签  |
|  task   | 适配   |
|  worker  |  解析 拼接  |
|  java-runtime  |  解析  |
|  nodejs-runtime  |  解析  |
|  python-runtime  |  解析  |
- 对应需要拼接函数名的组件，环境变量添加如下数据，根据环境变量FUNC_BRANCH，判断拼接的分隔符，值域如下

|  值域  |  说明  | 备注 |
|:---|:---|:---|
|  0   | yuanrong   | 默认选项 | 
|  1  |  FunctionGraph  |     |

需要添加环境变量出发点如下：
- 	URN的解析与拼接时公共方法，本身没有配置项
-	当前每个组件都在增加开关，控制是否是FG的分支，虽然定义的字段的意义不一样，但是实际上的作用是一样的，目前组件都在增加配置，最好是能够统一
-	此环境变量可以通过helm全局变量或者构建脚本，判断是否需要设置在环境变量中，默认没有，则是对应的黄区分支，common会提供util来获取跟判断
