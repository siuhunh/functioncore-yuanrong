# AR.SR.55dc059d.001 【functioncore】防计费偷跑功能在runtime异常场景下保证功能正常，补充进程状态的校验

## 1. 需求场景分析

场景：当前元戎支持防计费偷跑功能，在请求结束3s之后，没有再次调用，worker会向runtime-manager发送暂停runtime进程的请求，防止用户的函数继续执行偷跑计算资源

### 1.1 特性需求来源与价值概述

需求来源：ICSL渗透管理部在进行代码白盒检视时，发现暂停机制是通过遍历/proc目录来获取snuser用户的进程，并向相关进程发送暂停信号，如果成功影响此动作，则能够阻止函数进程进入暂停状态

价值概述：防计费偷跑功能可靠性加固，防止用户通过构造异常导致防计费偷跑功能失效，进而偷跑资源

### 1.2特性场景分析

1、函数调用结束3s后，没有再次接收到调用请求，则worker会向runtime-manager发送暂停runtime进程的请求
2、runtime-manager接收到worker发送的请求后，遍历/proc目录下的所有snuser用户进程，并向相关进程发送暂停信号
3、发送暂停信号为异步请求机制，无法保证进程一定被pause
4、在此期间，如果用户函数不断向自身进程发送recover信号，则可能导致pause信号异常，进程无法被暂停
5、补充进程状态的最终校验，在接收到worker重新恢复runtime进程的请求之前，校验runtime进程的状态是否为暂停
6、若发现状态异常的进程，则认为计费偷跑功能异常，runtime-manager进程退出，函数实例退出

## 2. 特性/功能实现原理

1. 函数调用结束3s后，worker向runtime-manager发送暂停请求：  
    // ProcessPauseEvent pause runtime process
    func (p *ProcessLimit) ProcessPauseEvent(client *tcpmsg.SocketConn) {}
    
2. runtime-manager对当前进程状态进行校验，若进程已经为暂停状态，则不会处理请求
    process.Manager.CurrentRuntime.Status == tcpmsg.RuntimeProcessStatusPaused

3. 若进程非暂停，则遍历进程及其子进程
    runtimeProcessEntry, err := utils.GetSelfAndSubAndOrphanProcessEntries(runtime.Uid, runtimeProcessPid)

4. 向遍历得到的进程发送pause信号
    err = syscall.Kill(pid, sig)
    
5. 信号发出后，补充进程状态的校验
    err = checkProcessStatus(pid, sig)

### 2.3 约束

1、runtime异常重连场景下，不会进行进程暂停，防止进程持续异常，此为计费偷跑功能正常设计
2、本可靠性场景只考虑通过阻止runtime接收暂停信号异常所导致的计费偷跑功能异常

#### 2.3.1上下游依赖需求

无

#### 2.3.2其他约束

由于1分钟内持续无请求调用，则函数实例会被回收，因此无法实现一次调用，长时间偷跑
