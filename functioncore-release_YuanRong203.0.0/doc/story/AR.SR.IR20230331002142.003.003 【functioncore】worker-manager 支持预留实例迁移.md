# AR.SR.IR20230331002142.003.003 【functioncore】worker-manager 支持预留实例迁移

## 1. 需求场景分析

1. 出于降成本考虑，现网需要下线一部分节点
2. 预留实例可能运行在节点上，导致节点无法达到下线的条件
3. 需要把节点上存在的实例迁移到其他节点上，同时，不能影响业务函数正常运行

### 1.1 特性需求来源与价值概述

- 需求来源：降成本，解决由于存在预留实例而无法下线节点的问题
- 价值概述：支持迁移预留实例到其他节点，不影响业务运行的情况下，方便节点下线，降低成本

### 1.2 特性场景分析

正常场景：

- CA 插件下线节点前，先给节点打上污点标签

```shell
# CA 插件给节点打污点标签
kubectl taint node 10.244.162.244 DeletionCandidateOfClusterAutoscaler=123456:PreferNoSchedule
# CA 插件删除节点污点标签
kubectl taint node 10.244.162.244 DeletionCandidateOfClusterAutoscaler-
```

- 手动下线节点前，先给节点打上污点标签

```shell
# 手动给节点打上污点标签
kubectl taint node 10.244.162.244 node.kubernetes.io/unschedulable=123456:PreferNoSchedule
# 手动删除节点污点标签
kubectl taint node 10.244.162.244 node.kubernetes.io/unschedulable-
```

异常场景：

- 实例迁移失败的场景

  - 新实例拉起失败，重试三次，每次间隔 5s
  - 老实例删除失败，重试三次，每次间隔 5s
  - 实例迁移需求优先保障函数运行不受影响，如果出现集群环境原因导致迁移失败，采取重试，重试未成功，则取消这个实例的迁移动作

## 2. 特性/功能实现原理

### 2.1 特性

- 感知节点被打上特定污点标签
- 删除节点原有的 Pool Pod
- 为待迁移的实例创建新的实例 pod
- 新的实例 pod 承载函数请求
- 删除老的函数实例 pod，老实例执行优雅退出

计费考虑：

- 普通实例按照调用量来计费的，不存在多计费的问题（Init 阶段的计费是否需要考虑？）
- 给节点打上污点标签后，给节点上所有的预留实例发送一个请求，要求停止计费。
- 节点污点标签被删除时，向节点上的预留实例发送请求，恢复计费。
