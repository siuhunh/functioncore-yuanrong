# 【functionCore】【可运维】梳理高危操作和规范化操作

## 1. Story整体设计

### 1. 功能描述
梳理高危操作和规范化操作，输出一个操作规范化文档。当运维人员登录了我们现网环境，依据此文档规范操作，保证数据面运行正常。

### 2. 场景分析
运维人员登录我们的现网环境，在没有规范操作文档的指引下，可能会出现某些高危操作，导致数据面运行异常，例如误删除数据面组件deployment，误删除数据面组件pod.

### 3. 方案详细设计
梳理高危操作，主要分为三大类：人为因素，操作系统方面和数据库方面
规范化操作

#### 高危操作-人为因素
1.非正规途径的脚本或代码在一线部署
2.未经客户授权，私自修改现网数据
3.生产环境和测试环境同时操作
4.未经一线授权，私自启停现网应用
5.现网操作直接手动敲命令

#### 高危操作-操作系统方面
1. 随意使用rm –r删除现网环境上的文件
2. 使用find和awk遍历话单和日志
3. 长时间使用tcpdump获取抓包信息
4. 随意使用helm uninstall、helm upgrade、kubectl delete、kubectl edit等命令

#### 高危操作-数据库方面
1. 未经客户授权，私自新增、修改和删除数据库数据
2. redis：使用了keys等消耗资源的命令、日志老化批量删除日志，导致CPU超高，触发主备倒换。
3. mysql: 使用 for update 方式更新数据；
4. mysql: 业务高峰时段使用大表关联查询统计数据；
5. etcd: 使用etcdctl get --endpoints=ip:port --prefix / --keys-only 查询所有key等全量查询操作。

#### 规范化操作
运维人员提前整理运维需执行相关命令及说明，然后提交运维申请。由运维和研发责任人进行审核，审核通过后，才可在现网环境进行运维操作。
如果运维命令是常用的，且不会影响现网环境的，可输出到规范文档进行记录，方便快速审核使用。
如果出现特殊情况需立即登录现网环境进行运维操作，相关运维和研发责任人需在旁辅助指导操作人员，避免出现高危操作。

## 2. 可信软件

1. 安全性（Security） 
   *【系统对恶意威胁的防护能力。可能的威胁包括但不限于未授权访问、使用、泄露、破坏、修改、毁灭；防护目标是保持信息的机密性、完整性和可用性】* 
   不涉及
2. 韧性（Resilience）
   *【系统受攻击时保持在有定义的运行状态（包括降级）、遭遇攻击时快速恢复核心系统、受攻击后在业务需要的时间窗内恢复到有效运行态】* 
   不涉及
3. 隐私性（Privacy） 
   *【系统具备能力能使客户（含组织和个人）能够就收集、使用、保有、披露和处置个人信息履行其权利和义务】*
   不涉及
4. 可靠性（Reliability）
   *【在给定的条件、给定的时间区间能无失效地执行要求的能力】*
   不涉及
5. 可用性（Availability）
   不涉及
6. 安全（Safety）
   *【系统失效导致的危害不存在不可接受的风险，不会伤害自然人生命或危及自然人健康，不管是直接还是通过损害环境或财产间接造成的* 】
   不涉及
