# AR.SR.IREQ02597546.035.018 cache manager内存数据持久化

## Story 整体设计

### 功能描述
**背景说明**  
为提升cache-manager组件可靠性及可维护性，需要将cache-manager组件内存中的数据进行持久化落盘处理，
以便cache-manager出现异常重启时能够从磁盘中进行部分数据恢复。
**功能描述**  
cache-manager组件通过配置挂载evs，组件内存中的数据持久化至evs中，evs是华为云提供的服务。
**用户体验**  
cache-manager作为冷启动优化特性的专用组件，用户不会对其有非常明显的感知，只是在之前未进行数据持久化的版本中，
若组件异常，则需要重新进行函数部署创建或者元数据配置信息修改，才会让cache-manager重新进行代码缓存，此特性完成后，
组件的异常重启将不会再产生此影响，冷启性能会更加稳定一些。

### 场景分析
cache-manager内存数据持久化的需求为数据面独立需求，与管理面组件无关。
cache-manager内存数据持久化的需求需要evs服务的支撑作为落盘目标，因此此特性开发完成后，需要在环境部署时，注意evs的提前挂载操作

### 方案详细设计

#### 方案设计
1. cache-manager接收到函数部署事件时，除在内存中缓存外，另起协程进行数据落盘

2. cache-manager依据objectID（样例：functions/c53626012ba84727b938ca8bf03108ef/Autotest/InvokeFunction_Python27_01/latest/index.zip）
进行md5加密（样例：0c9cfe58594b9f062a0730fc880e3f28），生成1、2级落盘目录（最后1位为一级目录，倒数2、3位为二级目录），同时落盘函数的checksum

3. 如果落盘前发现磁盘中没有对应数据存在则直接落盘

4. 如果落盘前发现磁盘中有对应数据存在，则进行checksum校验，相同则不处理，不相同则删除本地落盘文件并重新落盘

5. cache-manager初始化启动时或cache-manager与etcd之间断链时，除接收etcd的缓存事件外，还要从本地磁盘中加载函数代码至内存，
若两者冲突，均以etcd中的函数checksum为准，同时更新磁盘数据

6. worker向cache-manager发送拉取函数代码请求的处理逻辑不变，仍然为直接从内存中读取数据，
worker本身有checksum校验机制，如果从cache-manager拉到的是跟etcd中不匹配的代码也是不会继续进行特化的
