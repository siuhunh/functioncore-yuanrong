# 【functionCore】【可靠性】支持redis故障期间数据可缓存上报

## Story 整体设计

### 功能描述

**背景说明**

为了增强模块的可靠性，需支持redis在故障的期间，数据可进行缓存上报；redis故障
，模块数据写入三次失败后会丢弃数据，为了保证数据的完整性，需要添加redis-cache来存储暂时无法写入redis的数据

涉及Redis写入场景（需要缓存守护）：

1.

**功能描述**

在redis故障场景下，为防止丢失的数据过大，内存无法完全容纳，先将无法写入redis的数据可
以写入磁盘文件Redis-Cache作持久化处理，等redis恢复后，读取磁盘数据写入redis，并上报成功；保证一个月 99.95%
可用，经时间计算，可容忍20分钟的可用性故障；20分钟写入redis的数据量作为持久化缓存的参考

**用户体验**

### 场景分析

redis在发生可靠性故障场景下，集群失效，数据无法写入。需要在磁盘中构建一个缓存文件来持久化未能写入的redis数据。

| 序号 | 写入场景                 | 写入类型 | 是否缓存 |
| ---- | ------------------------ | -------- | -------- |
| 1    | Node信息（CPU内存）      | string   | 否       |
| 2    | 报告函数实例个数         | string   | 否       |
| 3    | 上报连接池信息           | HASH值   | 否       |
| 4    | 上报失败的费用           | string   | 是       |
| 5    | 上报预留实例费用         | 列表     | 是       |
| 6    | 上报时间段内使用资源数据 | 列表     | 否       |
| 7    | 上报异步回应信息         | string   | 是       |

### 方案详细设计

#### 方案设计

1. 模块（如fnAccess、fnInsMgr等）在redis可用的期间正常写入数据；
2. 在redis故障期间，讲数据写入模块节点的/tmp/Redis-Cache文件中，根据业务内存，写入除了资源上报之外的其他信息，根据可靠性要求，可以最多保存20分钟的数据；
3. Redis故障恢复后，将/tmp/Redis-Cache文件中的数据读取出来，并写入redis；写入完成后删除该文件
