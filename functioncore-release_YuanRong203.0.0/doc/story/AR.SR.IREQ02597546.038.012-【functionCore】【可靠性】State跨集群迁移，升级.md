# AR.SR.IREQ02597546.038.012-【functionCore】【可靠性】State跨集群迁移，升级

## Story 整体设计

### 功能描述

FunctionGraph支持状态跨集群迁移，保证状态的高可用性，提升用户体验

### 场景分析
1. state-manager监听元数据etcd
2. 节点下线状态释放时，由所有集群的state-manager抢夺

#### 方案设计
- **state-manager感知状态释放** <br/>
  监听元数据etcd中的/sn/workers字段，感知到某个functiontask的字段的删除事件，则去/sn/stateworkers查找是否有此NodeID <br>
  如果有此NodeID，代表需要此NodeID对应的状态被释放，需要抢夺更新

- **state-manager抢夺状态更新** <br/>
  每个state-manager自身会在内存中维护集群内可用节点，会选择一个本集群内最合适的节点尝试更新(先删除再重写)/sn/stateworkers字段的NodeID信息 <br>
  使用redis分布式锁保证唯一性，使用setnx接口，key为stateID，持有此状态的锁的statemanager才可以更新etcd信息
  增加恢复机制，抢到的写失败了，下次调用重新分配的机制

#### 外部交互分析&&上下游依赖需求
丁震 busproxy跨集群通信&状态ID使用全局etcd

### 对外接口
无新增对外接口

### 约束
etcd续租时间8s，有节点下线还未来得及抢夺状态时，则会有短时间此状态不可用 
切流升级时会出现被切流的集群持有的状态断流问题
抢夺时可能会出现某个集群状态负载过高的问题
