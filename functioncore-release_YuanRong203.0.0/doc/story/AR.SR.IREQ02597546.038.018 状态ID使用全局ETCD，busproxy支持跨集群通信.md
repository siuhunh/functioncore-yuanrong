# 【functionCore】状态ID使用全局ETCD AR.SR.IREQ02597546.038.018

## Story 整体设计

### 功能描述
**背景说明**  
当前融合版本现网部署架构为双AZ、4集群模式，为了适配多集群部署下的有状态函数调度，需要状态路由信息写入全局ETCD（元数据ETCD），且busproxy支持跨集群通信

**功能描述**  
若处理状态的节点为集群1的task1，那么当修改该状态的请求发送至集群2后，集群2的task能够通过状态路由感知到集群1会处理此状态，从而将请求转发，保证请求依然能正常处理

**用户体验**  
用户不感知数据面内部的调用流程，但是充分利用多集群接收函数请求，可以有效降低集群负载

### 场景分析
1230现网版本中，有状态函数只能通过函数互调接口进行调用，在无状态函数调用有状态函数的场景下，由于无状态请求分发的不确定性，需要确保有状态函数的处理能正确分配到指定节点的task上

#### 方案设计
state-manager 对接元数据etcd 
  
  1、当前state-manager的部署对接路由ETCD，通过读取路由ETCD中proxy的节点注册信息，在接收状态请求时进行状态的节点分配。
  2、为保证所有集群的state-manager能够感知到所有的状态路由信息，需要由路由ETCD切换为对接元数据ETCD
  3、state-manager对状态路由进行watch，当其他集群进行路由分配后，其也能进行感知，以便进行后续的路由分发
  4、当其他集群进行状态路由删除时，state-manager也需要进行感知，更新自身维护的状态路由信息缓存
  5、由于所有task都会向元数据etcd进行信息注册，state-manager需要从四个集群的task中识别出本集群内的task，并将其纳管
  
bus-proxy感知元数据ETCD且向其中写入并续租节点信息
  
  1、由于state-manager切换为只对接元数据ETCD，为继续能采集节点信息，需要bus-proxy向元数据ETCD中写入相关信息，并续租（与路由ETCD操作相同）
  2、bus-proxy异常时，续租失败，state-manager能感知到节点下线

bus-proxy支持跨集群通信
  
  1、当前元戎数据面4个集群部署在同一VPC网络内，不同集群task间可以互相访问（需要打开节点安全组配置--在环境部署时需要注意）
  2、proxy向state-manager发送请求获取状态所在节点信息后，向指定目标节点发送请求进行状态处理
