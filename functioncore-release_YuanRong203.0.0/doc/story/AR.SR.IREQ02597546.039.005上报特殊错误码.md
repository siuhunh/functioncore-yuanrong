# 【functionCore】在函数启动失败，或者init退出后，上报特殊错误码

## Story 整体设计

### 功能描述git

**背景说明**

防止受到攻击耗光资源，返回特定错误码，考虑所有runtime

**功能描述**

在函数启动失败的时候，如果Pod会退出，消耗资源，则及时上报错误码错误信息通知管理面；或者函数在初始化场景时候发生失败，
也需要及时上报错误码错误信息通知管理面。

**用户体验**

出现此类错误，用户感知，得到错误信息和错误码通知

### **场景分析**

1.自定义函数的bootstrap脚本执行失败(如脚本中途退出，语法错误，或者找不到脚本文件)，会导致runtime重启也无法恢复，从而使pod退出，造成资源损耗；


2.基于不同的runtime，初始化函数执行阶段失败，无法获取和响应用户函数调用，Pod退出，造成资源损耗；


针对以上两种场景，需要添加错误码与错误信息，反馈到管理面，防止受到攻击从而耗尽资源

3.其他会导致Pod退出消耗资源的特殊场景，待梳理,如后续要添加持续改进

| 序号 | 导致Pod重启的异常场景                | 原报错信息码                                               | 修改后的信息码 |
| ---- | ---------------------- | :------------------------------------------------------ | ---- |
| 1 | 用户函数初始化失败 | runtime.Error(int(errorInfo.Code) | FunctionInitFailCode = 4201 |
| 2    | 函数找不到bootstrap文件 | RuntimeBootstrapNotFound：4012 | RuntimeBootstrapNotFound：4202 |
| 3    | 用户bootstrap脚本未执行完退出 | RuntimeProcessExited：4016 | RuntimeProcessExited：4203 |
| 4   | 用户bootstrap脚本语法错误 | RuntimeProcessExit：4013 | RuntimeProcessExit：4204 |
| 5 | 用户函数OOM | RuntimeMemoryExceedLimit：4018 | RuntimeMemoryExceedLimit：4205 |
| 6 | 用户磁盘挂载失败 | RuntimeMountErrorCode : 4017 | RuntimeMountErrorCode : 4206 |
| 7 | 磁盘超出 | DiskUsageExceed : 4015 | DiskUsageExceed : 4207 |


### 方案详细设计

#### 方案设计

1. 的bootstrap脚本执行失败场景发生情况下，pod特化退出，定义成特殊的错误码（42XX），定义导致Pod重启的error-message，返回至管理面，
   用户感知，并配合黑名单进行处理；
2. 初始化函数执行失败，内部错误或者用户操作（如客户函数语法、入参、超时、OOM等问题初始化失败）导致Pod退出，
   将此错误码（42XX）与error-message错误信息返回至管理面，使用户感知并配合黑名单进行处理。




管理面的黑名单需求要与本错误码对齐，管理面需要配合错误码进行黑名单管理，进行联调。黑名单策略（如针对42XX的返回错误码）
由管理面设计。如黑名单函数禁请求一段时间。
