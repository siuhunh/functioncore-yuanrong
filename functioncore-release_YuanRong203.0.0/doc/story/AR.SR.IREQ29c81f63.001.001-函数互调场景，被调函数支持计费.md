# 函数互调场景，被调函数支持计费

## 1. 需求场景分析

### 1.1 特性需求来源与价值概述

本需求只针对函数互调场景，被调函数支持计费场景。

### 1.2特性场景分析

当前正常函数调用的计费:

单实例单并发： 根据请求response将计费信息带回。

单实例多并发 和 预留实例：每5分钟由worker将计费信息发放给bus，由bus写入到redis中。

所以对于被调函数是单实例多并发或是预留实例时，无需修改可以复用。对于单并发的场景下，通过请求返回来获取计费信息，无法计费。

所以本次主要针对单实例单并发的被调函数进行计费。

对于单实例多并发和预留实例的被调函数，再请求进来执行时，每五分钟上报一次计费数据到bus，与原来保持一致。

针对单实例单并发的被调函数，本次采取同样和单实例多并发的上报方式一致，由worker五分钟进行一次上报。
