# 【安全】worker与pat-service之间安全通信加固

## 1. 需求场景分析

### 1.1 特性需求来源与价值概述

本需求来自与之前送检问题的加固。送检问题如下：

**问题描述&影响：**

1. Worker组件下载并解压zip包时，由于未做有效的相对路径校验，导致用户可以通过zip包内文件路径以../开头的相对路径的方式，把文件解压到其他目录下

2.  由于Worker组件拥有cap_dac_override权限，导致用户利用zip目录穿越后，可以把文件解压到系统目录下
3. Worker的vpc相关功能特性，会周期性的用exec.Command方式调用ping，如果攻击者用上述的方式，在系统目录下(如/usr/local/bin)解压一个ping的二进制文件，由于环境变量PATH的设置，该二进制可以替代原有的/usr/sbin/ping，被Worker调用起来

4. 至第3步，攻击者已经获取到了Worker容器内sn用户权限，进一步的攻击思路，a) 容器内有证书密钥登鉴权/认证相关物料，攻击者可以进一步攻击集群内其他服务，如etcd，obs等； b)攻击者可以尝试做容器逃逸的攻击

当前代码中已经增加了路径校验，不存在上述解压打其他目录的问题。再一次对ping命令防止替换进行加固。

### 1.2特性场景分析

再一次针对ping命令防止替换进行安全加固。

### 2.1总体方案

1. worker启动时获取一下ping二进制的sha256值。
2. 在网络校验返回前，校验一下当前的ping二进制的值是否与启动的一致。一致说明没有替换掉ping，不一致则返回失败，说明被替换掉。
