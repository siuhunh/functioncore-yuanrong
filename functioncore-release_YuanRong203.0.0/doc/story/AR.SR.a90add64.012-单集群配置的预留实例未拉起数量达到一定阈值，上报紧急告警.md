## 2. 特性/功能实现原理

### 2.1总体方案

*该章节主要阐述该特性的详细设计，包括选择什么器件，使用什么算法，架构如何布局，打算UI**如何呈现，希望获取什么用户信息支撑后续设计等。*

1. 因为拉起预留实例的过程不会有用户错误，只有系统错误导致的无法拉起，因此拉起预留实例的逻辑保持现有的指数级时延增长的无限重试逻辑
2. workerManager内存信息中已经记录了实例map和配置的预留实例数量，通过处理现有的内存信息已经可以判断是否需要告警
3. 复用common中带告警抑制的告警模块，实现上报告警和消警
4. 15min检测一次，放在环境变量中可配置。需要在functionCache中新增一个预留实例的timestamp字段记录预留实例中元数据的变化时间，超过15min的才走入判断逻辑，防止15min内的误告警
