# DTS2023112205199-数据面通信链路适配管理面快速校验，签名中添加请求body体相关内容

## Story 整体设计

### 功能描述
**背景说明**  

为了防止函数请求数据，在调用过程中互相串了，需要对每个请求进行数据一致性校验。

管理面相关需求：

https://clouddevops.huawei.com/domains/551/design_desktop

**功能描述**  

frontend、busproxy、worker 组件根据请求 header 和 body 对请求进行数据一致性校验。  

### 场景分析
管理面的请求中，截取 body 前 10 、后 10 的字节，加上 body 长度，组成字符串，base64 编码，放到 header 中，数据面的 frontend、busproxy、worker 组件中对 inovke 请求的数据一致性进行校验。


### 方案详细设计

#### 方案设计

**请求数据一致性校验方案**

取请求 body 的前 10 个和后 10 个字节，以及 body 的长度，组成字符串，base64 编码，跟请求 header 中的签名字段进行比较，如果两个字符串内容一致，则说明请求数据一致。

```go
func GetContentSignature(payload []byte) string {
    payloadLen := len(payload)
	var extractStr string
	if payloadLen <= payloadCheckLen {
		extractStr = string(payload) + strconv.Itoa(payloadLen)
	} else {
		extractStr = string(payload[:payloadExtractLen]) + string(payload[payloadLen-payloadExtractLen:]) +
			strconv.Itoa(payloadLen)
	}
	return base64.StdEncoding.EncodeToString([]byte(extractStr))
}
```

备注：该方案由管理面提供，管理面已完成串讲，方案中的校验算法不能完全保证一致性，已经和SE知会该风险，确认按照当前方案开发。

**涉及组件**

- frontend

  InvokeHandler 方法中，如果 worker 返回数据不一致的错误，frontend 基于收到的消息做一次校验：

  worker 失败，frontend 校验成功，说明管理面传递的数据正确，返回 worker 的错误码 161911，由管理面重试。

  worker 失败，frontend 校验失败，说明管理面传递的数据错误，返回 worker 的错误码 161911，由管理面重试。

- busproxy

  busproxy 发送给 worker 的请求，在请求的 Extra 字段中新增 x-content-signature 字段。

  如果 worker 返回数据不一致的错误，busproxy 基于收到的消息做一次校验，日志打印校验结果。

- worker

  Adaptor 方法中，新增对请求数据一致性的校验：从请求的 Extra 字段中获取 x-content-signature 字段，从请求 RawData 中拼接签名字段，比较两个字段内容是否一致。（数据一致性校验只对 frontend 的请求做，不涉及函数互调）

  校验失败返回 ContentInconsistentErrorCode 161911。【新增错误码，更新 wiki】

  校验失败，打印失败日志，日志中包含校验时间。

  worker 环境变量新增 CONTENT_SIGNATURE_CHECK，在 worker-manager 特化 pod 时配置；worker-manager PoolMgrConfig 新增WorkerContentSignatureEnable，在环境变量 POOLMGR_CONFIG 中配置。
