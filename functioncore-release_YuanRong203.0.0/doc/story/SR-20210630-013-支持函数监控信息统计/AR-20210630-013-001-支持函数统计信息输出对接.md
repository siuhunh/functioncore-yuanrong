# 【FunctionCore】支持函数统计信息输出对接


## 1. Story整体设计
### 1. 功能描述
需求： 
其余指标functionGraph通过invoke-summary进行采集，所以​YuanRong只需要统计函数的当前实例数，写到redis，由funcgraph的omsvc统计上报。

### 2. 场景分析
1. ​YuanRong定时统计函数的当前实例数，上报到redis。funcgraph的omsvc从redis读取。最后用户可在functionGraph的函数指标界面，看到函数当前实例数统计曲线。

[FunctionCore支持函数监控信息统计-Open Model](https://cloudmodeling.tools.huawei.com/projectspace/detail/2928afd8ae624e609af7b0148bf05fad?projectDiagramUUID=a91810f186d04e2da66e314049f55336&versionUUID=)

### 3. 方案详细设计
方案. 在instance-manager开启一个定时任务，定时统计函数的当前实例数.

instance-manager内的workercache缓存了函数对应的最大实例数、最小实例数和对应的worker实例列表，针对本需求新增一个当前实例数map`workerCurrentCount map[string]int64`,
其中key的格式为`projectID@package@functionName@version`，value为函数的当前实例数，当AddWorker和DelWorker函数被调用时更新workerCurrentCount内函数的当前实例数.

定时任务每隔60秒读取`workerCurrentCount`，将其转换成json写入redis，key为`metrics_function_instance_Cluster_ID`。

在instance-manager配置文件新增Cluster_ID字段。

注：
1. 定时任务只在leader角色的instance-manager上启动，并且在启动60秒后进行第一次数据采集。
2. instance-manager异常重启，缓存在workercache的函数实例信息会丢失，所以在初始化workercache时需查询etcd恢复数据。
3. 定时统计周期：60秒
4. workerCurrentCount转换成json写入redis, 需考虑缓存大小限制问题，String类型的value值上限为512M，按每个函数0.2KB, 可以存储260万个。

### 4. 上下游依赖需求

functionGraph的OMSVC定时采集上报到redis的函数当前实例数指标。
