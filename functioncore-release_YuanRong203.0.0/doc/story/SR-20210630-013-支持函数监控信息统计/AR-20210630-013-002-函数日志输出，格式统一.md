# 【FunctionCore】函数日志输出，格式统一


## 1. Story整体设计
### 1. 功能描述
需求：  

函数日志输出，格式统一；

融合策略：确保元数据包括日志格式所需所有信息，支持按照functiongraph格式和目录要求输出日志。

### 2. 场景分析
1. 用户函数日志，worker和runtime服务日志按照functiongraph格式和目录要求输出。

### 3. 方案详细设计
1. 当前用户函数日志（user-function.log）、worker日志（worker-run.log）和runtime日志挂载目录示例：
```
/var/lib/kubelet/pods/26b27ce3-5780-4bf2-93bc-79c05e67c193/volumes/kubernetes.io~empty-dir/varlog/worker-run.log
/var/lib/kubelet/pods/26b27ce3-5780-4bf2-93bc-79c05e67c193/volumes/kubernetes.io~empty-dir/varlog/user-function.log
/var/lib/kubelet/pods/26b27ce3-5780-4bf2-93bc-79c05e67c193/volumes/kubernetes.io~empty-dir/runtimelog/python-runtime.log
```

2. 目录整改functiongraph要求将用户函数日志和worker日志挂载到不同目录，用户日志在stdlogs目录下，worker和runtime的日志在servicelogs目录下，示例如下：
```
/var/lib/kubelet/pods/26b27ce3-5780-4bf2-93bc-79c05e67c193/volumes/kubernetes.io~empty-dir/stdlogs
/var/lib/kubelet/pods/26b27ce3-5780-4bf2-93bc-79c05e67c193/volumes/kubernetes.io~empty-dir/servicelogs    
```

3. 用户函数日志文件，文件名和日志格式统一：
``` 
/{project_id}/functionName@package@version@podName@time@logGroupId@logStreamId.log  
```
注：logGroupId和logStreamId，新增到用户函数源信息。

用户函数日志字段：  
|          字段名称     |                             字段含义                  |                          示例                       |     
| :---------------- | :----------------------------------------------------------: | :------------------------------------------------: |
|        podName      |     实例(pod)名称    |     cff-runtime-3072m-5d75d75c84-hwgpp       |   
|        projectId    |     账号project_id  |     397cd10b30544c588b2f4a56d83856c4       |   
|        package      |   包(app)           |           default      |   
|        function     |   函数名           |           pwc_test2       |   
|        version      |   函数版本         |           latest       |    
|        stream       |   stdout          |  stdout       |  
|        time         |   日志时间         |    2021/5/27 7:51       |
|        requestId    |   请求id           |  89d6791d-1af5-4af4-a20c-814d3087c790   |
|        instanceId   |   实例(pod)id      |  270b13fb-bebf-11eb-a2d9-fa163eb0dd58   |    
|        errorType    |   错误类型，当前有超时、内存超限、磁盘超限、代码异常  |  TimeOut/MemoryExceedLimit/DiskTmpUsageOutOfRange/RunningError   | 
|        stage      |   函数执行阶段，当前有initialize和invoke状态  |  initialize/invoke   | 
|        status     |   执行状态(异常包括超时、内存超限、磁盘超限、用户代码执行异常)，当前判断errorType为空则success  |  success/fail   | 
|        log        |   具体日志            |  2021-05-27 15:51:43.011+08:00 Start initialize request '89d6791d-1af5-4af4-a20c-814d3087c790', version: latest\n  | 

注：status 在尾日志（Finish invoke or Finish initialize）体现.

示例：
```
{"podName":"cff-runtime-128m-ddfc54c66-4swvl","projectId":"05250099ad00d57c2fb4c00e4df7911c","package":"default",
"function":"get_article","version":"latest","stream":"stdout","time":"2021-04-26 06:23:49.878",
"requestId":"a78c4f04-299c-4882-a5da-b7eabf08e1bf",
"log":"2021-04-26 14:23:49.862+08:00 Finish initialize request 'a78c4f04-299c-4882-a5da-b7eabf08e1bf'(initialize Failed), 
duration: 16.606ms, billing duration: 100ms, memory used: 57.707MB\n"}
```

4. worker和runtime服务日志统一
functionGraph对worker和runtime服务日志的文件名和日志内容无格式要求，所以日志文件名和日志内容格式不变。

补充：servicelogs目录下需新增一个info文件，说明该服务日志所属函数，info文件命名规则如下：
projectID:function:package:function-name:version.info


### 4. 上下游依赖需求

​	funcgraph对上述日志进行采集
