# 函数执行详情

## Story 整体设计

### 功能描述
如果函数调用请求需要回显日志，会显示最大 4k 的日志，超过4k则保留首尾并删除中间日志。


### 场景分析
 worker 需要限制返回的长度最大为 4k ，将多余日志截断处理。


### 方案详细设计

#### 现状分析
元戎当前实现，日志经一条一条 base64 编码后，通过 “，” 拼接， 如果大小超过 4k ，则截断并返回。
问题：如果返回日志因编码后数据截断，导致了解码失败，忽略该错误，仅返回请求结果。

#### 方案设计
参考 FunctionGraph 的实现，为使 base64 编码后日志大小小于 4k ，将用户日志限制为 2k （继承FunctionGraph的实现），超过则截断，另外补充头尾的 'Start request' 和 'Finish request' 的日志记录信息，然后再进行 base64 解码。
元戎也同步这个设计。

无

### 约束
用户调试日志显示的大小小于4k。
